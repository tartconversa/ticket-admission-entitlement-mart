# 事实仓设计说明

本文件说明联票事实仓如何把陆续到达、彼此冲突的交接记录变成可追溯的事实，
以及每条业务规则落在哪个模块。代码只依赖 Python 标准库与内置 SQLite。

## 1. 分层：原始层只追加，派生层全量重建

- `raw_records`：交接原件，按 `(source, line)` 幂等追加，永不更新、永不删除。
  双发回执、被作废的声明、错误的批次声明都保留在这里。
- `dim_* / fact_*`：每接收一批资料就基于当前掌握的全部原件整体重建。晚到
  记录、券号补发、批次补正因此都会触发重新判定，而不是用新结论覆盖旧结论。
- 结算侧的历史结论不通过修改旧行表达，而是追加“反向差额”行，始终指回
  原票与原结算行，保证场馆已出具的凭证可以一直对上账。

入口在 `factware/engine.py` 的 `ingest()` 与 `rebuild()`。

## 2. 凭据、到场与消费资格

- 同一 `receipt` 可能被中心（HUB）与亭双发：`fact_receipt` 只承认最晚到达的
  签字声明，全过程保留在 `fact_receipt_statement`（`superseded` 标记被取代项）。
- `entered` 与 `reentry` 是有效到场；`denied` 是拒绝尝试，`void` 是作废，
  后两者不产生到场经历。
- 再入场（带 `link` 或补发券）保留为**独立到场经历**（`fact_attendance`），
  但 `consumes=0`，不重复消耗、不重复计费。
- 消费资格按**谱系根**归并：`ticket_issues.csv` 的明确换发关系把补发券接回
  原券，`build_lineage()` 求出每张券的根。两个确实不同的入场各自保留，
  但同一资格在同一场只计一次消费。
- 票号资格按券号核对：扫描记录的券号没有对应票权时进入 `ingest_errors`
  隔离，不会挂到同伴的券号下。
- `void` 后资格恢复未使用（`consumed=0`），但原始入场痕迹保留在
  `voided_receipt`，结算据此同时保留原计费行与反向差额行。

## 3. 场次审计边界：缺批按待查

- 每个 `(亭, 场馆, 场次)` 只承认最高 `serial` 的声明，因此离线亭用更高流水号
  补正错误的 `complete` 时，齐备性会被推翻回待查。
- 场馆的亭全集来自该场馆所有批次里出现过的亭。一场次必须被**全部已知亭**
  以 `complete` 覆盖才算资料齐备；已知亭缺该场次边界本身就是缺批。
- 换票评估时，未入场成员的原场次若未齐备，只能 `pending`，不能据此判
  “未入场”而承诺新场次。

## 4. 换票决定

`fact_exchange.decision` 的取值与含义：

| decision | 含义 |
|---|---|
| `promised` | 整组仍能作为一组兑现，名额已预留 |
| `pending` | 原场次核验资料未齐，按待查处理，不占名额 |
| `blocked` | 成员已入场但缺场馆陪同批准 |
| `rejected` | 券清单与联票组不符、无票权或名额不足；未交付待单可拒绝 |
| `claimed` | 承诺已领取并冻结，等待交付 |
| `frozen` | claim 之后晚到核验改变了成员资格，等待人工处置 |
| `released` | 承诺已释放，名额回流可售池 |

关键规则：

- 只能在组合票仍能**整组兑现**时承诺；`tickets` 必须与联票组成员完全一致，
  不允许只换组内部分券。
- 已核验成人换场需要场馆明确的陪同批准（`companion_approval`，任一事件行
  携带即可），且成人仍占用新场次人数，成人已有消费不被抹掉。
- 名额需求按谱系根去重，补发券不重复占名额。多个换票在同一名额池上互相
  扣减；少任一所需名额都不能承诺。
- `frozen` 会列示受影响同行成员、待释放名额与是否已实际接管
  （新场次出现该谱系成功入场才算接管）。冻结期间名额仍被占住，客服不能
  立即转卖。
- 一家被拒或挂起不影响其他家庭的正常处理。

## 5. 场馆结算与对账

- 计费单位是消费资格而不是扫描次数：一个谱系根在一场最多一条 `payable`，
  再入场不另计。
- 依赖同行核验的儿童，只有同行事实可证实才结算：成人成功入场不晚于儿童、
  且在儿童之前 30 分钟内（`coupled_condition_holds`）。
- 确认期按场馆声明的到达顺序开放。常规资料归入到达时已开放的最后一个
  确认期；作废产生的反向差额只能进入**严格晚于**资料到达批次的下一开放期，
  绝不回写已关闭的旧期；晚于最后一期的资料挂 `PENDING-` 等待下次确认。
- 反向差额行通过 `prior_settlement / prior_receipt` 指回原票与原结算行。
- 场馆凭证（含更正）原样保留在 `fact_venue_statement`；`fact_reconciliation`
  按凭据净额比较，给出 `matched / difference / missing_venue_confirmation`。

## 6. 输入检查与隔离

- `factware/validation.py` 做单条记录的字段、取值域、时间与数字校验。
- 未通过的记录进入 `ingest_errors`，不污染任何事实表；读取阶段的格式问题
  （表头、列数、未知文件）同样登记。
- 同一目录重复接收时 raw 层幂等，已存在的原始声明不会被静默改写；业务上
  的“后来补正”应表现为新到达批次的新记录。

## 7. 模块索引

| 模块 | 职责 |
|---|---|
| `factware/sources.py` | 读取 CSV/TSV/JSONL 交接目录 |
| `factware/validation.py` | 单记录字段校验与类型规范化 |
| `factware/store.py` | SQLite 表结构、只追加与重建 |
| `factware/model.py` | 券号谱系、同行 30 分钟条件 |
| `factware/engine.py` | 凭据/消费/审计/换票/结算全部判定 |
| `factware/queries.py` | 客服与场馆两个视角的查询视图 |
| `factware/cli.py` | 命令行入口 |
| `factware/timeutil.py` | UTC 时间解析 |
